## 2. 当前代码现状总览

在正式跑整套实验之前，先对当前工程状态做一个务实判断。

### 2.1 当前代码已经具备的能力

当前 `main.py` 已经支持下面这些关键实验开关：

- `--use_afs`：启用 AFS 异常感知特征选择
- `--use_rrs`：启用 RRS 残差选择定位
- `--use_synthetic_anomaly`：启用特征级 Perlin 合成异常
- `--use_pixel_anomaly`：启用像素级合成异常
- `--pixel_anomaly_prob`：控制像素级异常采样概率
- `--perlin_anomaly_prob`：控制特征级异常采样概率
- `--anomaly_strategy`：控制统一异常控制器策略
- `--eval_anomaly_map_source recon/rrs`：控制评估时使用重建残差图还是 RRS 输出图
- `--enable_enhancement`：对特定类别启用边界增强分支

也就是说，从模块设计上看，论文方法的大部分主线已经在代码里有对应实现。

### 2.2 当前代码暂时不够完善的地方

这一部分非常关键，因为它直接影响实验是否能顺利落地。

#### 2.2.1 没有稳定的 checkpoint 保存/加载机制

当前训练脚本是“边训练边评估写日志”的模式，没有看到稳定的：

- `torch.save(...)`
- `checkpoint`
- `resume`
- 独立 `test.py`

这意味着：

- 当前适合直接做“训练过程中记录最佳结果”的实验；
- 不适合先训练完再统一离线评估和批量可视化；
- 如果后面要系统生成 Fig.3/Fig.5，建议先补一个“保存最优模型 + 独立测试导出异常图”的工具脚本。

#### 2.2.2 可视化代码目前是注释禁用状态

`main.py` 中用于导出 anomaly map 的几组函数目前都被注释掉了，例如：

- `visualize_evaluation_anomaly_maps`
- `visualize_anomaly_maps_simple`

这意味着：

- 当前定量实验可以做；
- 当前定性图生成流程还不够顺手；
- 后面要做 Fig.3 / Overlay 图时，最好单独补一份推理导出脚本。

#### 2.2.3 `eval_anomaly_map_source=rrs` 的 PRO 评估存在已知报错风险

现有日志 `mvtec.log_5_1_rrs_bottle` 显示，在使用：

```text
--eval_anomaly_map_source rrs
```

时，`compute_pro(...)` 出现过维度断言报错：

```text
AssertionError: amaps.ndim must be 3 (num_test_data, h, w)
```

结合 `util/test.py` 判断，问题大概率出在：

- RRS 输出的 anomaly map 维度与 `compute_pro` 期望维度不完全一致；
- 单张图送入 `compute_pro` 时又额外包了一层维度。

因此，**在正式跑像素级 PRO 为主的实验前，建议优先修复这一问题**。

#### 2.2.4 论文中的部分实现细节数值需要以后期代码参数为准

从 DOCX 文本抽取结果来看，`4.2.2 Implementation Details` 中有少量学习率、公式、尺寸位置没有被纯文本完整解析出来。后面最终定稿时建议遵循：

1. 实验真实运行参数以代码命令行为准；
2. 论文正文中的参数描述再根据最终命令统一回填。

## 3. 正式实验前的准备顺序

建议不要一上来就全量跑表格。最稳妥的流程是按下面顺序推进。

### Step 1. 确认数据集目录

当前代码默认从 `./data` 读取数据，MVTec 目录结构应为：

```text
data/mvtec/<category>/train
data/mvtec/<category>/test
data/mvtec/<category>/ground_truth
```

VisA 目录结构应为：

```text
data/visa/<category>/...
```

另外，如果某些 MVTec 类别要启用前景约束像素异常，训练集目录下还可以存在：

```text
data/mvtec/<category>/train/foreground_mask
```

若没有该目录，代码会自动退化为全 1 mask，不会报错，但像素级前景约束会变弱。

### Step 2. 先修复 RRS 评估维度问题

这是当前最优先的实验前修复项。否则：

- 主结果中的 Pixel AUROC/PRO 统计可能不稳定；
- 参数敏感性图和可视化论证都会受影响。

建议修复点：

- `util/test.py` 的 `get_eval_anomaly_map(...)`
- `evaluation_pixel(...)`
- `compute_pro(...)` 调用前的 anomaly map shape 对齐

目标是保证：

```text
anomaly_map.shape == [B, H, W]
```

并且单样本传入 `compute_pro(...)` 时为：

```text
(1, H, W)
```

### Step 3. 跑单类别 smoke test

建议先只跑 `bottle` 或 `capsule`，验证：

1. 训练可以走完；
2. 每轮评估正常输出；
3. Image/Pixel/PRO 都能打印；
4. AFS、RRS、Hybrid anomaly 三条链路都没有 shape 错误。

建议直接使用当前最新主线思路做一次单类实验。

### Step 4. 再扩展到 MVTec 全 15 类

单类验证通过后，再开始：

- 主结果全类实验
- 主消融实验
- 参数敏感性实验

### Step 5. 最后补可视化与图表整理

等定量结果稳定后，再集中做：

- Fig.3 定性对比图
- Overlay visualization 图
- 参数敏感性图最终重绘

这样效率最高，也最不容易返工。

## 4.3.2 Ablation Study：消融实验如何落实

这一节是全文实验最重要的部分之一，因为它直接验证每个创新模块是否真的有贡献。

建议拆成 4 组。

### 4.3.2.1 Group A：递进式主消融

对应论文中的 **Table 2**。

#### 目标

验证完整方法的性能提升是否来自模块逐步叠加，而不是单点偶然增益。

#### 建议配置组

1. Baseline CKAAD
2. Baseline + Hybrid anomaly
3. Baseline + Hybrid anomaly + AFS
4. Baseline + Hybrid anomaly + AFS + SAME
5. Full model: Hybrid anomaly + AFS + SAME + RRS

#### 代码落实方式

当前代码更适合通过开关来控制：

- 关闭 Hybrid anomaly：
  - 不加 `--use_synthetic_anomaly`
  - 不加 `--use_pixel_anomaly`
- 关闭 AFS：
  - 不加 `--use_afs`
- 关闭 RRS：
  - 不加 `--use_rrs`
  - 或评估时强制 `--eval_anomaly_map_source recon`

SAME 目前是 AE 主干内建结构，没有单独显式开关。如果要做严格的 “w/o SAME” 消融，需要进一步在模型代码里补一个关闭注意力套件或退化为普通 encoder-decoder 的开关。

因此，本组实验要区分两种情况：

#### 情况 1：如果暂时不改代码

可以先完成：

1. baseline
2. + hybrid anomaly
3. + hybrid anomaly + afs
4. + hybrid anomaly + afs + rrs

#### 情况 2：如果要和论文叙述完全对齐

建议补充：

- `--disable_same` 或等价开关

这样 `Table 2` 会更严谨。

### 4.3.2.2 Group B：Hybrid anomaly 消融

对应论文中的 **Table 3**。

#### 目标

验证像素级异常与特征级异常是否互补。

#### 建议组别

1. 不使用合成异常
2. 仅特征级 Perlin 异常
3. 仅像素级异常
4. 像素级 + 特征级混合异常

#### 代码落实方式

1. 无合成异常：

```text
不加 --use_synthetic_anomaly
不加 --use_pixel_anomaly
```

2. 仅特征级异常：

```text
--use_synthetic_anomaly
不加 --use_pixel_anomaly
```

3. 仅像素级异常：

```text
--use_pixel_anomaly
不加 --use_synthetic_anomaly
```

4. 混合异常：

```text
--use_pixel_anomaly
--use_synthetic_anomaly
```

#### 建议固定其余设置

```text
use_afs = True
use_rrs = True
same 设置不变
```

### 4.3.2.3 Group C：AFS 选择策略消融

对应论文中的 **Table 4**。

#### 目标

验证性能提升是否来自“异常感知筛选准则”，而不只是单纯减少通道数量。

#### 建议组别

1. All channels
2. Random selected channels
3. Fixed ratio truncation
4. AFS selection

#### 代码现状判断

当前 `model/afs.py` 已实现：

- AFS selection

但没有直接提供：

- random channel selection
- fixed front-half truncation selection

因此要完成严格的 Table 4，建议补两个小对照实现：

1. `RandomAFS`
2. `FixedSliceAFS`

如果暂时不想改主代码，也可以先通过“手工修改 AFS 索引生成逻辑”单独跑一轮对照，但不建议长期这样做，因为不利于复现。

### 4.3.2.4 Group D：RRS / residual strategy 消融

对应论文中的 **Table 5**。

#### 目标

验证 residual selection 的必要性，以及 `max + mean` 的合理性。

#### 建议组别

1. reconstruction map only
2. max only
3. mean only
4. max + mean

#### 代码现状判断

`model/rrs.py` 当前默认是：

```python
modes=['max', 'mean']
```

理论上可以支持：

- `['max']`
- `['mean']`
- `['max', 'mean']`

但 `main.py` 里 RRS 初始化方式当前是写死的，没有命令行参数直接切换模式。

因此建议后续补一个参数：

```text
--rrs_modes max
--rrs_modes mean
--rrs_modes max mean
```

如果不补这个开关，这组消融很难规范化批量执行。

### 4.3.2.5 本节最终产物

本节最终建议至少形成 4 张内部实验表：

1. 主消融表
2. Hybrid anomaly 消融表
3. AFS 策略消融表
4. RRS 策略消融表

### 4.3.3.1 本节目标

### 4.3.3.2 建议保留三组敏感性实验

### 4.3.3.3 Group A：AFS retention ratio

#### 对应论文图

Fig.4(a)

#### 需要改动的参数

当前 `main.py` 中可通过：

```text
--afs_select_planes
```

对于 `wide_resnet50_2 + layer 1 2 3`，原始通道大致对应：

```text
256, 512, 1024
```

因此建议四组比例设置为：

- 25%: `64 128 256`
- 50%: `128 256 512`
- 75%: `192 384 768`
- 100%: `256 512 1024`

### 4.3.3.4 Group B：Hybrid anomaly probability

#### 对应论文图

Fig.4(b)

#### 需要改动的参数

```text
--pixel_anomaly_prob
--perlin_anomaly_prob
```

建议四组设置：

1. `0.10 / 0.20`
2. `0.20 / 0.30`
3. `0.30 / 0.30`
4. `0.40 / 0.40`

其余样本自动作为 normal 保留。

### 4.3.3.5 Group C：RRS strategy

## 7. 最终建议

从顶刊写作标准来看，当前实验部分的主线已经是对的，但落地层面还缺少两个“工程支点”：
